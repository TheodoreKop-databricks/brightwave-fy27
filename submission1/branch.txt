  On this branch (writes are copy-on-write isolated from production) we wrote a scenario table:
    CREATE SCHEMA scenario;
    CREATE TABLE scenario.replicate_all_forecast AS
      SELECT ar.recommended_action, count(*) campaigns,
             sum(cp.recoverable_spend_usd) total_recoverable_spend,
             avg(ar.predicted_roas_lift)  avg_predicted_roas_lift,
             sum(cp.recoverable_spend_usd * ar.predicted_roas_lift) projected_recovered_value
      FROM synced.campaign_position cp
      JOIN synced.open_underperformers ou USING (campaign_id)
      JOIN synced.action_recommendations ar USING (campaign_id)
      WHERE cp.perf_band='underperformer' AND cp.status='active'
      GROUP BY ar.recommended_action;   -- see forecast_scenario.sql / branches_result.json

  Forecast: replicating the matching winner across all 59 eligible underperformers projects
  ~$23.8M recovered value (+2.24 avg ROAS lift); reallocating the other 30 projects ~$4.78M.

  Isolation proof: the `scenario` schema exists on forecast-scenario but NOT on production
  (branches_result.json → isolation_proof). The branch's TTL means it costs nothing long-term.
